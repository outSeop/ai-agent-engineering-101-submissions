# R4 재고 관리·재가동 검증 — 2026-11-25

구현 담당은 Codex GPT-6.2 Sol, 운영 판단은 수업 모델이다. R3의 마지막 실제 배포본과 일치하는 방법을 확인해 R4 규약에 맞게 이식했다. R3 판매 기록·지갑·고정 원화 한도는 가져오지 않았다.

## 적용한 방식

- 툴이 실제 재고, 판매·노출 시간, 품절 요청, 미확정 매입과 현금 위험을 계산한다. 실정산·양의 기여 근거가 없는 상품을 검증 품목으로 올리지 않는다.
- 모델은 공개 상품 정보와 툴이 만든 가능한 품목·수량/비교안에서 선택하거나 구체적 위험 때문에 보류한다. 신규 SKU는 한 개씩 여러 종류를 시험할 수 있다. 실측 0을 초기 탐색 자체의 금지 사유로 쓰지 않는다.
- 공급창 전에 승인하고 같은 창에서 최신 재고·현금·예약·가격·비용을 다시 검사한다. 초기 운영은 창당 3라인, 정책상 최대 10라인이다. 65% 재고 목표는 가이드이고, 80% 자본 노출과 현금 완충금은 제한이다.
- 식품은 실제 잔여기한이 승인 보충 시간에 처리 여유 3분을 더한 기준 이상이어야 한다. 신규 시험은 최소 2시간 3분이다. 부적합한 단위가 섞이면 묶음 전체를 송금 전에 거절한다.
- 견적, 송금, 시장 수락, 정확한 단위 ID의 입고는 별도 상태다. 송금이 불명확하면 새 송금을 막고 같은 quote/tx와 시장 증거로 대조한다. 시간이나 같은 SKU 총량만으로 예약을 해제하지 않는다.
- 고객의 공개 대화로 매입을 실행할 수 없다. 고객 판단과 재고 판단은 별도 경로다. 재고 운영 모드에서는 일반 ReAct의 중복 모델 호출을 제거했다.

## 데이터 경계

실제 현금·예산·미확정 비용·재무 위험·거래 내역·고객 데이터는 로컬 계산에 남긴다. 재고 모델 입력은 `public_model_view`로 공개 카탈로그와 허용 수량 메뉴만 투영한다.

자동 승인 검토가 거절한 이전 재무 문맥을 다른 경로로 재전송하지 않았다. 공개 메뉴로 최소화한 별도 대안이 검증·승인됐다. 키·토큰·권리코드는 모델 메시지와 공개 증거에 넣지 않는다. 시장 토큰은 기존 발급 시장의 공식 API 인증에만 사용한다.

## 검증 결과

- 회귀·독립 테스트 **67개 통과**: 금융, 고객, 프로필, 브로커, 워커, 조달, 데이터 최소화.
- 실제 수업 모델의 고객 모의 **7개**와 원 단위 조건부 구매 **1개** 통과. 가격 문의와 구매 수락 분리, 서명 원문 전달, 혜택, 환불 검토, 중복 방지를 확인했다.
- 실제 수업 모델의 신규 분산 매입·현금 보호·검증 품목 보충 **3개 모의 상황** 통과. 임시 키·가상 은행·가상 공급자를 사용했다.
- 공식 고객 코드의 모의 구매·정산·환불도 통과했다. 모의 가격은 4,500에서 대기할인 45와 기존 마일리지 45를 적용해 4,410이었다.
- 공식 forge 출처: `a2a_info v8`, `stock_procurement v3`, `publish_shop_info v1`. 공식 키트 7개 파일은 원본을 유지했다.

## 실제 운영과 구분

R4는 기존 신원·지갑·재고·장부로 재가동했다. R3는 계속 중지한다. 공개 카드에 마일리지와 대기할인의 조건을 표시했다. 재가동 직후 읽기 전용 운영자 문의는 실제 수요·판매·정산으로 세지 않는다.

실제 신규 매입·정산은 `runtime/operations` 관측과 시장 원장으로 별도 확인한다. 이 문서의 모의 테스트 성공은 실제 매출 성과가 아니다.

30분 간격의 이 채팅 heartbeat **R4 운영 점검과 개선**을 생성했다. 관측기는 읽기 전용이며 운영자 기록과 Windows 보고서를 갱신한다. 연속 가동이 1시간 미만이면 이전 30분과 현재 30분을 정상 성과 비교라고 말하지 않는다. R4 순위는 공개되지만 점수 차이는 공개되지 않는다.

초기 워커 재시작은 터널 준비 전 연결 검증 실패에서 발생했고 재시도 뒤 정상 연결됐다. 메모리 누수와 구분해 기록한다. 데이터 최소화 적용을 위한 정지는 의도한 유지보수로 별도 기록했다.

## 시행착오

- 독립 테스트의 가상 공급자가 여러 상품에 같은 quote/unit ID를 재사용했다. 안전장치가 이를 거절했다. 실제처럼 ID를 유일하게 만들었고 중복 방지 검증은 완화하지 않았다.
- 가상 바이어 결제의 은행 주소와 도매 공급 은행이 달랐다. 동일한 가상 은행과 현금 차감으로 테스트를 보정했다.
- 첫 실제 모델 보류는 단순히 판매 실측이 없다는 이유였다. 초기 소량 학습과 사전 승인의 목적을 명확히 했다. 모델이 고른 수량을 도구가 늘리거나 예산 목표를 강제하지 않는다.
- 제출 자료 복사는 원본별 비밀 검사를 먼저 요구받았다. 선택한 원본을 실제 키·토큰·JWT·상세 추론과 대조 검사했고 실제 운영 스냅샷·DB·고객 원문은 제외했다.
