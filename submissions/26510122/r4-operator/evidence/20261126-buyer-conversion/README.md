# 셀러 대화·구매 전환 경로 수정

기존 고객 문의에서 직전 상품을 다시 묻고, 재고가 없는 상품의 대안을 보여주지 못하며, 명시적으로 결제서를 요청해도 별도 구매 명령을 요구했다. `public_catalogue_runtime_v4d`는 같은 A2A task의 검증된 공개 상품만 이어받고, 모델이 실제 재고 대안을 고르며, 현재 요청의 대상이 하나로 확인된 서명 결제서 요청을 기존 결제 도구로 보낸다.

## 역할과 보존 범위

- 모델: 요청 해석, 실제 재고 중 관련 상품 선택, 대안·응답·견적 도구 선택.
- 기존 genuine `public_catalogue@5`: 실제 공개 상품 검색·상품명·포장·가격·등급·남은 시간 렌더링. 원 forge/logic/permission/test 네 파일을 바꾸지 않았다.
- 외부 host: SDK task가 이어지도록 공개 상품 표시를 `input_required`로 전달, 5분/최대300 task의 SKU·등급·공개 가격만 기억한다. 고객명·claimed_from·이전 원문·주소·JWT·권리코드를 기억하거나 신원/금융 권한으로 사용하지 않는다.
- 기억한 상품도 현재 요청에서 재조회한다. 현재 명시 SKU가 우선이며 여러 후보를 임의로 하나로 정하지 않는다. 구매 동의와 비공개 권리는 현재 발언에서만 확인한다.
- 여러 검색 페이지는 같은 원본 SHA의 검증 페이지 최대6개·각8행, 실제 선택 최대3개만 합친다. 가격·SHA 충돌이면 기억 저장을 닫는다.
- 대안은 원래 요청 상품이 검증되지 않았음을 분명히 표시하고 기존 genuine 렌더 결과를 그대로 붙인다. 다른 상품으로 자동 결제하지 않는다. C 제외·대안 거절을 존중하며 성분/알레르기·설치·호환성을 임의로 확약하지 않는다.
- 결제서 발급은 송금/정산 완료가 아니다. 현재 단일 대상과 명시적 발급 요청이 필요하다. 철회·인용·단순 질문·모호한 대상·검증하지 못한 조건은 발급하지 않는다. 가격상한은 상품가 기준이며 배송·고정 all-in 총액 같은 보장으로 확대하지 않는다.
- 실제 서명·재고 재검증·원가하한/예산·예약·권리/대기권/마일리지·동시성은 기존 dispatcher에 유지한다. 원 금융 코드를 바꾸거나 예약을 풀지 않았다.

예약 `r4/r4-2/r4-3`은 모두 PAUSED다. 셀러 자체 매입·홍보 루프, 정산 워커, 내부 캐시/Card timer는 유지한다. DB·두 지갑·매입·혜택/환불 정책·원 SDK7 파일도 유지했다.

## 검증

- 최종 host 회귀 15/15, 독립 금융 경계 7/7, 교차 페이지 독립 경계16/16, 원 금융 executor/실제 SQLite 동시성6/6.
- 실제 원 SDK ASGI·수업 모델로 baseline은 상품 안내 뒤 completed/동일 task 거절, 수정본은 동일 task 공개 기억 `[0,1,0]`과 genuine 재조회 응답을 확인했다. 마지막0은 다른 task의 음성 대조다.
- 실제 수업 모델이 명시 SKU의 결제서 요청에 quote_and_send를 선택했다. 해당 canary는 금융 executor stub/NoWallet이며 실제 결제서·송금·판매는0이다.
- 실제 수업 모델의 A/B 대안 선택은 원래 SKU 미검증 안내와 genuine 응답 suffix가 일치한다. 최종 v4d는 별도 A/B 페이지에서도 선택2개를 기억한다.
- 운영 공개 A2A에서 단일 SKU 안내→같은 task 후속, 별도 A/B 검색→2개 대안 표시와 task 유지까지 확인했다. 운영자 읽기 점검으로 별도 표시했으며 고객·정산으로 세지 않는다.
- 순수 함수/모의 검증과 실제 모델 검증, 운영자 조회, 실고객 정산은 별도 증거다. 원 SDK/금융 파일의 해시 검증은 initial-preservation-safe.json을 본다.

실행 예시(기존 Python 환경):

```text
.venv/bin/python -B evidence/20261126-buyer-conversion/test_public_product_continuity_v4d.py
.venv/bin/python -B evidence/20261126-buyer-conversion/independent-crosspage/test_crosspage_facts.py
```

위 두 portable 사본은 원 시험의 package lookup만 저장소 상대 경로로 맞췄다. 원 개발 실행 기록·실패·수업 모델 입출력은 private runtime에 보존한다. 원 검증 driver를 사용한 ASGI/실제 클래스 시험은 관측 cache·격리 작업 폴더가 필요하다. 원본 attempt 해시는 별도 manifest로 남긴다.

## 같은 시간 비교

comparison-plan-safe.json의 배포 전후 각1800초를 사용한다. 배포/운영자 검증 구간은 제외하며, 초기 v4c 관찰 창은 교차페이지 보완 때문에 폐기했다. baseline30분에는 문의/결제권/정산0이며 별도 보조2시간은4/1/1이다. 보조2시간을 사후30분과 직접 비교하지 않는다. 사후 창이 끝나기 전에는 증가/회복을 주장하지 않는다.

거래 기여이익은 실제 상점 수취액−해당 원 unit의 실제 매입 송금−매입 가스−신규 마일리지 전액 충당으로 계산한다. sale.cost를 실제 지출로 간주하지 않는다. 배치 균등 배분이 필요하면 따로 표시한다. 보유비·회비·운영비와 향후 환불을 완전히 배분한 상점 순이익은 아니다. 마일리지 사용은 이미 수취액에 반영되므로 다시 빼지 않는다.

## 남은 한계

같은 task의 공개 힌트는 5분 뒤 또는 재시작 시 사라진다. 현재 수업 buyer는 동기 대화이지만 범용 클라이언트가 한 task로 동시에 질문하는 경우 응답 순서까지 보장하지 않는다. 원 로컬 checkout에는 미결제 자동 TTL 해제가 없으므로 서명 후 재고가 장기 예약될 수 있다. 이를 임의로 해제하거나 오래된 JWT의 시장 유효성을 가정하지 않는다. 충분한 실고객 표본 전에는 전환 개선을 확정하지 않는다.
