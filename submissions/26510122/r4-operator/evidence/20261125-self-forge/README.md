# R4 self-forge evidence · 2026-11-25

The official kit and the live shop implementation are separate from these development artifacts. The four files under each generated tool directory are copied byte for byte from an official forge. They are experiments and are not approved for production deployment.

The official classroom model generated the original market-card reader. The official Mind also called a local Codex CLI bridge for development. The provenance file identifies the provider for matched model outputs and leaves upstream model identity unset because the bridge does not expose it. The host and independent QA code is Codex-assisted verification infrastructure. It is not classroom-model-authored business logic.

The actual classroom model used verified synthetic evidence to choose a refund approval. The approve event was recorded by the generated binding against the pinned fixture. Separate predetermined decline and needs-evidence cases exercised the response channel. They do not show autonomous denial on incomplete evidence. These were isolated cases with no wallet transfers or live ledger changes.

Earlier experimental failure summaries, independent fixture checks, and the pre-copy sensitive-data scan are included. Full original inference, ReAct and console logs stay private; SHA-256 references identify the snapshots read by the export. Production keys, tokens, customer rights, and real ledgers are excluded. Source files and sanitized test results may contain documented placeholders and synthetic data.

The QA scripts use the existing staged R4 fixture and the kit dependencies; they do not make live calls. Review prototypes that still use fixture-only gating or incomplete state transitions must remain out of production.


The actual classroom model called the reviewed public settlement summary tool in
the reach experiment. The subsequent model call received its aggregate-only
observation. The evidence exposes action and observation hashes with coverage,
rather than the observation body or any underlying ledger rows.

Run the packaged host tests with:
```sh
.venv/bin/python -m unittest discover -s deploy/self_forge_validation -p 'test_class*.py'
```

The historical v4 and v5 QA scripts require corresponding private pinned
candidate snapshots. They are included for inspection and do not target later
candidate versions. The results document their original pinned runs.
