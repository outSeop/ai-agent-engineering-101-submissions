# Shared request-front HOST sources

The only maintained Python implementation is these five files: admission_gate.py, front_edge_app.py, run_front_edge.py, transition_guard.py, config.py. A descriptor materializer copies them unchanged to runtime/releases/<id>/front and generates RUNTIME-BINDING.json + MANIFEST.json there. Generated releases are immutable runtime artifacts, not another tracked source implementation. Existing live deploy/front_compound_edge_runtime_v1 and its18809 store/gate are untouched.

Own MANIFEST.json uses a `files` SHA256 map including every shared source and RUNTIME-BINDING.json. The operator provides its expected SHA to the entry/guard. Config is loaded only after that manifest verification and must match its file hash. No A2A/customer values or port/runtime CLI overrides are accepted. Config JSON rejects duplicate/unknown keys. Example schema is tests/host_front/front-config.fixture.json; its synthetic runtime path/hash is test-only, not a real source claim.

Required top fields: schema='outseop-r4.front-release.v1'; new_port; old_proxy_port; marker; state_dir (canonical relative operator/runtime); service; runtime_path (absolute under fixed operator/runtime or deploy); runtime_manifest_sha256; main={service,pid_hint}; worker={service,pid_hint}; cf_pid_hint; preserved_edges ordered oldest→newest. Each edge is exactly {port,service,pid_hint,launcher,manifest_path,manifest_sha256,marker,state_dir}. Paths to old launchers are exact absolute paths, paired with their manifest folder. Services, markers and state folders must be distinct; new state cannot alias/overlap an old state. Old proxy is the newest preserved edge port; new port must be higher. Fixed security boundaries remain code constants: loopback source/destination, original origin18805, UID1000/comment, main/worker identities, original SDK7/financial hashes, no new business loop.

Optional semantic_instruction is null or a1–1500-character HOST instruction string (no NUL). After exact runtime broker file load and before assembly, the only prompt customization is broker.SEMANTIC_INSTRUCTION=config.semantic_instruction. Broker/financial body is not edited. If absent/null the base instruction is kept. This is operator-controlled model-interface text, not customer data or financial authority.

Entry CLI: `run_front_edge.py --operator OP --edge-manifest-sha OWN_SHA --sources-only` or explicit `--serve`. Port/runtime/service/state are config only. It creates one request listener, never cmd_run/join/Mind.loop/procurement/marketing. Original URL/wallet identity checks, one local Model decision budget and raw old-task forwarding stay unchanged.

Guard CLI: `transition_guard.py --package-manifest-sha OWN_SHA --sources-only`; actual root inspect/apply/rollback additionally use `--expected-new-edge-pid PID --expected-public-url ORIGINAL_HTTPS` and optional --apply/--rollback. Existing PID hints/units/launchers/manifest hashes come exclusively from config. New PID must use the launcher in the guard's own __file__ folder and matching --edge-manifest-sha; no fixed deploy folder is assumed. Preserved old processes may have legacy --port arguments or a manifest-bound config port. No prior service or CF is restarted.

Admission code is byte-identical to the proven v1: closed by default; persisted sticky possible-task count before SDK entry; zero is sufficient for rollback safety, positive may conservatively include failed requests; never reset missing history. Card/old-task proxy/known own-task continuations bypass readiness. Guard opens after strict postcheck, reverses only when closed/count0, and otherwise requires forward repair. Source-bound127.0.0.2 proxy keeps the NAT bypass. Schema, guard, budgets and wallet rights are not caller-selectable.

Focused tests: tests/host_front/test_front_protocol.py. Five synthetic ASGI/guard groups preserve prior gate/opaque-task/rollback behavior and check config hash tamper, state alias, semantic instruction bound, all old manifests/processes and exact self launcher. They perform no actual service/NAT/HTTP/Model/DB/wallet actions. Safe results are written only under runtime/compound-inquiry-20261128-audit. Live/canary validation remains the parent's separate task.

Test-only assemble accepts isolated_root=None by default. A provided fixture must be canonical/owned0700 under OP/runtime, with empty tool tokens/addresses and explicit options_override+toolbox_factory. Agent, Mind, app and returned Toolbox must all use that same root; actual source verification still reads only original public SDK/financial source files. The CLI has no isolated-root flag. Mock coverage checks this short branch and the single semantic instruction setter without loading production financial state.
