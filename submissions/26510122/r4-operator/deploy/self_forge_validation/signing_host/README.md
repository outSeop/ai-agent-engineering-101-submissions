# Address-serialized Signer host infrastructure

This directory preserves externally authored HOST security infrastructure and mock tests. It is not a genuine-agent-forged market business tool and must not be relabelled as classroom-authored code. serialized_signer.py is byte-identical to module SHA07d2eeb0f4e4d3f635035928135fc978120e93450695f27a4b94f2bfcc40e7f8; original test SHAe6ababe4a840c1552eba82e6751405f5ecb4fa719f291f0c8263b78a5b1f5e6e. The recorded final12 tests pass, with no failures/errors. The publication audit checked that result hashes match exact source and current7 SDK file hashes match recorded values. It did not rerun wallet mocks or make any real wallet/chain calls.

The factory returns an SDK Signer subclass; it does not load keys, edit original SDK files, create another production Signer, or install itself. It serializes original do(pay) by actual normalized address in one process, including authorization and receipt wait. Different roles sharing an address share the lock; different addresses can proceed independently. Original SDK capability/role/operation/amount limits are checked after acquiring the lock. sign/sign_jwt remain unchanged. Tests use fresh ephemeral keys, mocked maroo.pay and localhost HTTP only; no manual testing flags or real production key files are used by tests.

Current scope: NOT installed in the production launcher, NOT verified against actual transfers, and NO durable pre-send intent marker or ambiguous-send/receipt/nonce recovery business tool is completed. Process-local locking does not coordinate another process or a nonadapted sender. Revocation cannot cancel already authorized inflight broadcasts, and the original sent list is recorded only after pay returns. This factory therefore does not make refund/payment retries safe by itself. Future installation must preserve one main shared Signer instance across stock/refund and a stable role-wallet map.

Reproduction adapter (externally authored path infrastructure):

    <operator>/.venv/bin/python run_portable.py --operator <operator> --output /tmp/serialized-signer-mock-NEW

--output must not exist. The adapter copies the exact original module/test into a temporary directory with the original layout depth and links the existing official kit. It copies no keys/state and runs the original12 mock tests as main, retaining their loopback-only network guard. No test source rewrite is needed. The adapter was syntax/help checked only during publication; the preserved12-pass result is the existing hash-bound original run, not a newly claimed adapter execution.

validation/ retains original final unittest log/summary and loader contract metadata. The metadata's future injection is a proposal: a host hook may select the class before the original launcher creates its one Signer; it is not an installation record. publication-proof.json records four designated credential-byte/prefix comparisons and JWT/API-pattern scans before/after copy. Secret values or hashes are never exported. The production DB, keys/state, wallets, card, running services and launcher are unchanged by publication; only those four credential files were read in memory for the separate static scan.
