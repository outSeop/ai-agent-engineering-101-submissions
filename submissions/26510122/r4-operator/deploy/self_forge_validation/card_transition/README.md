# R4 card transition host candidates

This package contains externally authored host and verification infrastructure. The generated staging, application and maintenance tools have their own official forge manifests and are intentionally excluded here. Nothing in this package is evidence of a live deployment.

- `card_offer_producer_host.py` projects current legacy read-only offers and copies the public card into a fresh isolated session. `--prepare-only` disables model completion. It does not publish.
- `card_stage_recheck_controller.py` uses the official Mind and genuinely generated stage tool, limits selection to three SKUs, reconstructs an independent fresh view and checks that selected terms and original card are unchanged. It does not issue live authority or apply any card.
- `card_compact_view.py` formats all available rows in a bounded model observation. The actual stage continues to use the full verified data.
- `card_apply_authority_host.py` checks the provenance and expiry of a same-run generated staged record. It is not a publication renderer or executor.
- `card_guard_cutover_host_safety_candidate.py` is the reviewed operational candidate. It is dry by default. Explicit `--allow-fence` is reserved for the reviewed operating cutover. The earlier `card_guard_cutover_host.py` is retained only as regression evidence. It failed the two independent safety checks in the included summary.
- `managed_runtime_card_guard_candidate.py` is a production-baseline validation-only candidate. It permits the existing publisher and one exact read-only handoff guard bundle. It does not install itself.

Run from the operator directory with the private audited forge artifacts available:
```bash
PYTHONPATH=deploy/self_forge_validation:../round-4/codex-r4 \
  .venv/bin/python -m unittest discover \
  -s deploy/self_forge_validation/card_transition -p 'test_*.py'
```

The tests require the pinned `class-rebuild-reach-20261125` genuine source snapshots and the pinned pre-cutover legacy publisher bundle. These are evidence inputs, not generated by the tests. The tests execute dry/temporary fixtures and never start or restart the main service. The normal producer and controller invoke the market model only if explicitly run by an operator. Live fence, native authority and apply/rollback are separate operating steps.


The apply v2 host issuer requires verbatim approved policy wording from the
existing `repeat-benefits` and `refund-review` skill descriptions. A description-only
anchor is rejected. The external audit also verified a second v2 refresh and
rollback with stable skill anchors. Forge dependencies remain separately pinned.

The reviewed dry preflight command is:
```bash
.venv/bin/python deploy/self_forge_validation/card_transition/card_guard_cutover_host_safety_candidate.py   --operator "$operator" --session "$operator/runtime/card-cutover-<unique>"
```

`qa_card_guard_cutover_independent.py` is the original independent comparison
suite, preserved with its original private fixture paths. The accompanying
summary records 10/12 passing for the earlier installer and 20/20 passing
for the safety candidate (12 independent plus 8 regression tests).

The controller's optional in-process continuation accepts only same-run staged
evidence; CLI invocations do not install a continuation. A trusted callback
may return a compact native event receipt. The keeper preflight preserves the
existing SKU order and rejects changed terms without making a new selection.
The genuine stage v1 returns unchanged for identical offers, so this package
does not renew the original publication TTL or install a timer.
