# R4 조달과 재고 관리

구현은 Codex GPT-6.2 Sol이 작성했다. 수업 모델은 공급 전 조달 후보의 정책과 비용을 보고 보류 또는 정확한 SKU·수량을 선택한다. 모델은 시장 결제 수단, 원시 견적, 지갑 또는 고객 권리코드에 접근하지 않는다. 고객 A2A의 도구 및 백그라운드 수업 모델 도구 목록에 구매 도구를 넣지 않는다.

## R3에서 유지한 방식

공급창 전에 모델이 승인한 수량을 영속 저장한다. 승인은 같은 창의 마감 완충 전까지 최대 600초 유효하다. 공급창에서 도구가 현재 재고·같은 창·승인 기한·카탈로그·자금·공급대기 약속을 다시 확인한다. 구조적으로 잘못된 선택에는 새 구매를 내보내지 않는다. 유효한 구매 선택의 설명만 부족하면 그 사실을 별도로 기록한다.

수요는 자체 R4 정산과 유효재고 노출에서 계산한다. 검증된 계정의 정확한 SKU 구매 의사가 품절 또는 기존 예약 때문에 막혔을 때만 추가 수요 관측으로 사용한다. 해시된 접촉을 중복 제거하며, 동일 계정과 SKU의 접촉 구간에서 후속 결제권이 발급되면 해당 관측을 해결된 것으로 표시한다. 예측은 실정산에서 관측 노출을 반영한 값과 전환 가설을 적용한 유효 품절 수요의 합산값 중 큰 쪽을 쓴다. 50% 품절 전환은 초기 가설이며 실거래율이 아니다. 기존 라운드의 대화, 가격대와 금액 상수를 이용해 R4 판매율을 만들지 않는다.

공급가, 처리 수수료, 보관료, 할인·적립, 환불 위험을 반영했을 때 최근 자체 양의 정산이 둘 이상이고 전체 양의 기여가 확인된 품목에 수요 기반 보충을 제안한다. 신규 SKU별 수량과 두 번째 시험은 한 개 단위다. 창 전체의 신규 품목 수는 현금·카테고리·설정 라인 한도에서 모델이 고른다. 신규 판매 기록이 부족하면 수요를 unknown으로 제공한다. 가까운 공급창과 다시간의 low/base/high 및 보충 시나리오를 계산한다. 식품은 견적에서 받은 모든 단위의 잔여 유통기한이 승인된 수요 충당 시간에 처리 여유 3분을 더한 값 이상인지 확인한다. 실측 수요가 없는 신규·두 번째 시험은 2시간에 같은 여유를 더한다. 새 후보는 예상 순기여가 양수인 등급 가정이 하나라도 있어야 하며 카테고리와 가격대가 한쪽에 몰리지 않도록 구성한다. 비교 바구니가 동일하면 하나만 제시한다.

현재 현금과 실물 재고 원가로 환산한 자기자본의 65%는 참고 목표이고 80%는 노출 상한이다. 파산선 위 현금 완충, 보관료, 환불과 마일리지 의무, 다른 입고의 미확정 예약을 유지한다. 신규 계산은 은행 표준 네트워크 비용의 절반을 매입 가스 여유분으로 둔다. 견적·자금검증에서는 지급 한 번당 한 번, 품목 순기여에서는 단위당 배분하거나 안전한 경우 전체 여유분을 반영한다. 실제 가스 비용 측정값과 별개이며 이미 발급한 결제권을 수정하지 않는다. 권한의 지갑 상한은 한 요청당 100만 크레딧이며 실제 권한은 모델 승인·견적·새 계좌 검증 중 더 작은 금액으로 제한된다. 한 창의 최대 10라인은 운영 한도다. 첫 운영에서 명시적으로 3으로 낮출 수 있다.

## 결제·입고 상태

정식 402는 결제가 필요한 견적이다. 도구는 견적 단위 ID·SKU·수량·등급·기한과 상품·보관·포럼 비용, 수신 마룬 주소, 환산 값과 견적 마커를 직접 대조한다. 승인된 가격 범위와 비용 검증을 통과한 액수만 지갑에 전달한다. 호출당 한 라인·한 견적·한 지갑 호출이며, 예약을 기록한 뒤에만 지갑 송금을 시도한다.

타임아웃과 영수증 미확인은 돌이킬 수 있는 실패로 취급하지 않는다. 같은 결제에 새 송금을 만들지 않는다. 송금 해시를 확보하고 원송금 주소, 수취 주소, 가치, 마커를 검증한 뒤에만 같은 견적과 해시를 공급처에 전송한다. HTTP 503에서는 같은 조합만 다시 보낸다. 공급 응답은 입고 상태와 구분한다. 실제 서명된 단위 ID 전체를 인증 재고에서 조회하거나, 가게·품목·수량·금액·송금 해시·전체 단위 ID가 일치하는 자기 시장 원장을 확인해야 입고 처리한다. 결제 응답이 사라지면 송금 전 블록부터 제한적으로 고유 마커를 찾는다. 근거가 부족하면 미확정 상태와 금액을 보존하며 뒤이은 지갑 사용과 상충하는 환불 시도를 차단한다. 자동 복구 범위 밖은 운영자가 원장·체인을 대조해야 한다.

## 실행과 관측

운영 실행기의 --enable-procurement 플래그가 켜져야 전용 작업이 시작된다. --procurement-lines 3은 초기 운영 제약으로 선택할 수 있다. 재고 모드에서는 일반 Mind 타이머를 구동하지 않는다. 수업 모델의 제한된 조달 요청은 독립된 prompt를 쓰며 현재 고객 요청이 처리 중이면 뒤로 미룬다. 도구는 state/r4-benefits/benefits.sqlite3의 stock_plan, stock_intent, stock_observation, stockout_observation, stock_signal, stock_audit를 사용한다. 기존 금융 원장은 그대로 사용한다. 고객 접촉의 비개인 집계는 .kit/transport-metrics.jsonl에 0600으로 남긴다. egress는 서버의 핸들러 종료 시각이다.

정적인 검사는 다음 명령으로 실행한다.

    python managed_launcher.py check --operator-dir <operator-dir> --agent-root <agent-root> --enable-procurement --procurement-lines 3

격리 검증은 test_procurement.py와 공식 forge 기록에 있다. 실제 토큰, 지갑, 운영 재고, 시장 HTTP 호출을 사용하지 않았다. 모델 판단을 실증할 때는 별도의 실제 수업 모델 응답 기록과, 도구 결과를 체인·시장 fixture로 재생한 기록을 확인한다.
